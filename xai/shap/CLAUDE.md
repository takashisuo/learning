# CLAUDE.md — SHAPによる回帰予測値の要因分解プロジェクト

## 1. プロジェクトの目的

著名な回帰用サンプルデータを使い、SHAPで**予測値の構成を分解して見せる**分析を作る。
「どの特徴量が重要か」を並べるだけで終わらせない。ゴールは次の3点。

1. **予測値の構成(ミクロ)**: 1サンプルについて「ベースライン + 各特徴量の寄与 = 予測値」を示し、現在の特徴量の値でどう予測値が組み立てられているかが分かる。
2. **変数を動かしたときの変化(What-if)**: 「この変数をこれだけ上げると予測値がこれだけ上がる」「複数の変数を同時に動かすとこう変わる」を、実際のモデル再予測で定量的に示す。
3. **全体傾向(マクロ)**: データ全体で、各特徴量が予測値を押し上げる/押し下げる方向と大きさの分布、非線形な効果、特徴量間の相互作用を示す。

読み手は機械学習の専門家とは限らない。**目的変数の単位(元スケール)で語る**ことを最優先にする。

## 2. データとモデル

- メインデータ: `sklearn.datasets.fetch_california_housing`(目的変数 MedHouseVal、単位は10万ドル)
- 比較・検証用(任意): `load_diabetes`(特徴量が少なく動作確認向き)
- 分割: train/test = 80/20、`random_state=42`。乱数シードは全て固定する。
- モデル: LightGBM(`LGBMRegressor`)を第一候補。比較用に線形回帰(Ridge)も学習する。
  - 線形回帰ではSHAP値が係数×(x−平均)に一致するので、**SHAPの実装が正しいことの検証**に使う。
- 評価: test の R²・RMSE・MAE を表で出す。性能が低いモデルの説明は意味が薄いので、先に性能を確認し、結果に記載する。
- SHAPの説明対象は**テストデータ**とする(訓練データでの過適合した説明を避ける)。

## 3. 分析の必須項目

### 3.1 予測値の分解(ミクロ)
- `shap.TreeExplainer` を使い、`explainer.expected_value`(ベースライン=訓練データの平均予測)を明示する。
- 代表サンプルを選んで分解する(最低3件): 予測が高いもの / 低いもの / 中央値付近。選定基準を明記する。
- 各サンプルについて次を出す。
  - ウォーターフォール図(`shap.plots.waterfall`)
  - 分解表: `特徴量 | 現在の値 | SHAP値(元スケール) | 累積`。最後に「ベースライン + Σ SHAP = 予測値」を表示する。
  - 日本語の一文要約(例: 「ベースライン2.07に対し、MedIncが+0.82、Latitudeが−0.31…で予測は2.95」)
- **加法性チェックを必ず実行**: `|expected_value + Σshap − model.predict| < 1e-6`(許容誤差を明記)。満たさない場合は原因を調べて報告する。

### 3.2 What-ifシミュレーション(「上げるとどうなるか」)
SHAP値は「現在の値とデータ平均との差による寄与」であり、**「値を動かしたときの変化量」そのものではない**。そのため2種類を分けて扱う。

- **(A) モデル再予測による変化(正)**: 対象サンプルの特徴量を変更して `model.predict` を再実行し、予測値の差分を出す。これを「変化量」の根拠とする。
  - 単一変数: 各特徴量を +1標準偏差、または +10% 動かしたときの Δ予測値を一覧(トルネード図)。
  - 複数変数: 2〜3変数を同時に動かしたシナリオを数パターン定義し、Δ予測値を出す。
  - 動かす範囲は**訓練データの実在範囲(1〜99パーセンタイル)内**に制限し、範囲外は外挿として警告する。
- **(B) SHAPによる説明**: シナリオ前後でそれぞれSHAP値を再計算し、「Δ予測値のうちどの特徴量の寄与がどれだけ変わったか」を `Δ予測値 = Σ(ΔSHAP)` の形で分解して示す(シナリオ比較の積み上げ棒/ウォーターフォール)。
- 複数変数を同時に動かした場合の Δ予測値 と 各変数を単独で動かした Δ の合計との**差(=相互作用・非加法分)**を明示する。
- 依存プロット(`shap.plots.scatter`)で、特徴量を横軸、SHAP値を縦軸にして、「この変数がこの範囲だと予測がいくら上下するか」を読めるようにする。色には相互作用の強い特徴量を使う。

### 3.3 全体傾向(マクロ)
- beeswarm(`shap.plots.beeswarm`)と平均|SHAP|の棒グラフ。ただし**これだけで終わらせない**。
- 特徴量ごとの依存プロットを主要上位5〜8個について出す。
- `TreeExplainer.shap_interaction_values` で相互作用を計算し、主要な特徴量ペアの相互作用を示す(計算が重い場合はサブサンプル1,000件で行い、その旨を記載)。
- 予測値全体の構成: テストデータの予測値を「ベースライン + 特徴量グループ別寄与」に分解した**積み上げ図**(予測値の高い順にサンプルを並べる、または予測値ビンごとの平均寄与)。
  - 関連する特徴量はグループ化して合算してよい(例: 立地=Latitude+Longitude、住居=AveRooms+AveBedrms+AveOccup)。グループ定義は設定として明示する。

## 4. 解釈上の注意(結果に必ず明記すること)

- SHAPは**モデルの予測の説明であって、現実世界の因果関係ではない**。「MedIncを上げれば実際に住宅価格が上がる」とは言えない。「このモデルは上がると予測する」と書く。
- 特徴量間に相関がある(特にLatitude/Longitude、AveRooms/AveBedrms)ため、片方だけ動かすシナリオは非現実的になりうる。該当する場合は注記する。
- ベースラインは「訓練データの平均予測」であり、「0」や「標準的な家」ではない。
- 数値は必ず元スケールの単位付きで書く(例: 「+0.82(=約8.2万ドル)」)。
- SHAP値は目的変数がログ変換されていると加法の意味が変わる。変換を使う場合は元スケールとの対応を明記する。

## 6. 実装ルール

- Python 3.11+。主要ライブラリ: `shap`, `lightgbm`, `scikit-learn`, `pandas`, `numpy`, `matplotlib`, `japanize-matplotlib`(または同等の日本語フォント設定)。
- 図のタイトル・軸ラベル・凡例は日本語。特徴量名は英語のままでよいが、初出時に日本語の説明表を付ける(例: MedInc=地区の世帯収入中央値)。
- 関数に分けて再利用可能にし、ノートブックには呼び出しと解説だけを置く。
- 乱数は全て `SEED = 42` で固定。実行して同じ結果が出ること。
- 図は `outputs/figures/` に PNG(dpi=150以上)で保存。表は CSV で `outputs/tables/` に保存。
- 外部ネットワーク前提の処理は最小限にする(データ取得以外は不要)。
